## 대상과 실제 교정

### `k8s-theory-api-request-path.md`

제목이 다루는 범위를 생성 요청으로 구체화하고, APF·audit의 압축된 표현을 실제 동작으로 풀었습니다

- 원문: HTTP 요청 수명의 구간을 기록합니다
- 수정: HTTP 요청을 받아 응답하기까지의 주요 시점을 기록합니다

### `k8s-theory-authentication.md`

user.Info 예시와 인가 전달 절을 신원 설명 바로 뒤로 옮겼습니다. 토큰 갱신의 세부 조건은 뒤에서 이어 설명합니다

- 원문: projected volume 파일에 투영합니다
- 수정: projected volume을 통해 컨테이너 안의 파일로 제공합니다

제목에 인가의 판단 기준과 RBAC의 범위를 드러내고, 권한 합산과 위임 검사를 구체적인 주체·동작으로 표현했습니다

- 원문: 여러 규칙이나 여러 Binding에서 얻은 허용은 누적됩니다
- 수정: 여러 규칙이나 Binding에서 부여한 권한은 합쳐집니다

## 독립 검수와 보완

작성하지 않은 reviewer가 원문·수정본 3편을 전문 대조했습니다. 기술적 의미·조건 보존 오류는 발견하지 못했습니다. APF 대기·거부 설명의 인접 반복을 지웠고, 토큰 캐시의 '값은 캐시 유효 시간을'을 '값은 1분 동안 캐시하되'로 고친 뒤 인접 문맥을 재확인했습니다

## 보존과 검증

생성 요청과 저장·Pod 실행의 구분, 인증과 인가의 책임, 토큰 갱신 80%·24시간 및 캐시 1분·10초 조건, 삭제 허용 오차 60초, RBAC·bind·escalate의 적용 범위를 보존했습니다. 외부 실측이 아닌 소스 기반 설명이라는 주석도 남겼습니다

- 기준본과 source URL·이미지 경로의 개수와 값, 코드 블록, title·excerpt 외 front matter가 같습니다
- 바뀐 헤더로 향하는 저장소 내 fragment 링크를 확인했고, 끊어진 연결은 발견하지 못했습니다
- 현재 PostDetail과 같은 remark-gfm (`singleTilde: false`)·remark-cjk-friendly 설정으로 3편을 compileMDX 컴파일한 뒤 React 정적 HTML 렌더링에 성공했습니다
- 보호 대상 hash가 기준과 같습니다. 전체 빌드는 30편 편집 뒤 별도로 실행합니다
- lint·테스트 스위트·외부 기술 사실 재검증은 실행하지 않았습니다. 렌더링 검사는 문장 품질 판정으로 사용하지 않았습니다
