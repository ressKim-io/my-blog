## 편집 전 전문 독해와 연결 계획

### k8s-theory-network-policy

원문 전문과 검토서를 읽었습니다. 저장/집행 역할은 먼저 남기되 저장 strategy·status 내부 설명은 집행 구현 앞의 독립 절로 옮깁니다. 방향 격리·합집합 뒤에는 기존 selector 두 YAML을 먼저 배치해 적용 Pod와 허용 상대를 설명합니다. 포트 설명까지 읽은 뒤 policyTypes 생략·빈 목록을 비교하도록 합니다. 첫 selector 예시는 방향을 Ingress로 명시한 정책 안의 from 조각이라는 문맥과 적용 Pod·상대·포트의 연결을 보완하되 새로운 통신 실측이나 수치를 만들지 않습니다. ipBlock은 기본 선택과 빈 값 뒤의 주소 선택 확장으로 둡니다

### k8s-theory-admin-network-policy

원문 전문과 검토서를 읽었습니다. 현재 API의 설명과 Pass 사이에 있는 ANP/BANP 변천을 뒤의 BANP 제약 변화 앞에 합칩니다. subject·peer 최소 정의는 계층 그림 앞에 옮기고 구체적 선택자·포트·채널 제약은 평가 뒤에 둡니다. 외부 CRD와 구현 의존성은 첫 API 소개에서 보완합니다. 앞당겨지는 구형 ANP 규칙 수 언급은 풀네임을 붙여 역사 절을 먼저 읽지 않아도 지칭 대상을 알게 합니다

## 실제 변경

- NetworkPolicy의 기본 방향·합집합 뒤에 selector와 포트 설명을 두고 생략·빈 값 비교를 뒤에 연결했습니다. 저장 strategy와 status 한계는 집행 구현 앞에서 별도로 읽게 했습니다
- 관리자 정책은 subject·peer를 첫 판정 그림 앞에 옮기고 현재 액션·priority를 연속 설명합니다. ANP/BANP 대응 표와 유지·채널 상태를 BANP 제약 변화 앞에 모았습니다

## 미채택 제안과 이유

NetworkPolicy의 새 전체 YAML은 추가하지 않았습니다. 기존 selector YAML의 원래 가정과 코드 자체를 보존하면서 Ingress 방향·적용 Pod·상대·포트 관계를 인접 설명으로 연결했습니다. 빈 selector 문단은 두 selector의 AND/OR 비교 직후에 유지해 같은 필드의 의미를 이어 읽게 했습니다. 관리자 정책의 구형 ANP 규칙 수는 현재 수와 직접 비교하는 조건이므로 priority 단위에 풀네임과 함께 남겼습니다

## 보존 대조와 기술 확인

baseline front matter·코드·링크·이미지·인라인 코드 보존 검사 통과. 이동 경계를 재독해 적용 Pod와 상대, 양방향 허용, Pass와 최종 허용, 저장 검증과 fail closed를 구분하는지 확인했습니다. 기존 기술 주장을 새로 검증하지 않았으며 별도로 발견한 기술적 모순은 없습니다. 빌드·실행 테스트는 실행 안 함
