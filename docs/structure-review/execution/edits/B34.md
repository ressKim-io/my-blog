## 편집 전 전문 독해와 연결 계획

### k8s-theory-cgroup-v2-cpu-quota

원문 전문과 검토서를 읽었습니다. 20ms/21ms 가정 예시 다음에 cpu.max 파일 형식과 합산 예산을 바로 붙입니다. kubelet·CRI 작성 경로, milliCPU 계산과 limit 예외, shares 변환식은 커널 예산·부모 한도·weight를 이해한 뒤로 옮깁니다. fair-class 적용 범위는 cpu.max 첫 소개에 최소 문장으로 유지하고 CFS/EEVDF·빌드 조건 상세는 구현 보충으로 둡니다. CPU/메모리 비교의 기존 기술 내용은 삭제하지 않고 비교 단위 안에서 기본 차이와 상세 제어를 구분합니다

### k8s-theory-page-cache-reclaim-oom

원문 전문과 검토서를 읽었습니다. working set 식과 available 기본 설명을 처음으로 옮기고 page cache 비용으로 이어갑니다. reclaim 설명 안의 memcg/charge 정의는 그대로 먼저 읽히게 한 뒤 charge 회계·부모 한도를 연결합니다. LRU·MemoryQoS·hugetlb 상세는 기본 지연·OOM 설명 뒤로 옮깁니다. PSI는 OOM 앞에 두어 사용량과 지연의 차이를 먼저 닫고 원래 마지막 판단 문단은 보충 뒤의 결말로 보존합니다

## 실제 변경

- CPU 가정 예시 → cpu.max → 전역·CPU별 예산/부모·잔여·burst → weight → kubelet 계산/런타임 전달 → 통계 순으로 배치했습니다. CRI burst 전달 문단은 CRI 정의 뒤의 구현 단위로 함께 옮겼습니다
- 메모리 working set 식을 처음에 두고 회수·charge·부모 한도·PSI·OOM을 연결했습니다. LRU/카운터·MemoryQoS·hugetlb 상세는 그 뒤 독립 절로 보존했습니다

## 미채택 제안과 이유

CPU 글의 메모리 제어 상세를 링크만으로 대체하지 않았습니다. 요청된 기술 사실·조건 보존을 위해 원문의 MemoryQoS·oom.group 설명을 유지하고 소절 경계를 분명히 했습니다. 메모리 글의 memcg/charge 정의는 회수 절 안에서 유지해 이어지는 회계 설명이 미정의 용어로 시작하지 않게 했습니다

## 보존 대조와 기술 확인

원문 front matter·코드·링크·그림·인라인 코드 보존을 대조했습니다. 이동 전후를 재독해 평균과 주기별 소진, 부모 제한과 컨테이너 지표, working set과 실제 charge 범위, 지연과 OOM 기록의 차이를 확인했습니다. 새 기술 사실 재검증은 수행하지 않았고 별도 발견한 미해결 기술 의문은 없습니다. 빌드·실행 테스트는 실행 안 함

## 독립 검토 R1·R2 반영 계획과 근거

두 수정본의 첫 설명과 후반 상세, baseline의 대응 문단, 독립 검토 R1·R2를 대조했습니다. R1은 cpu.max 첫 범위 문장 바로 앞에 fair-class가 실행 가능한 일반 작업에 CPU 시간을 공정하게 배분하는 스케줄링 클래스라는 역할만 보완합니다. 후반 CFS/EEVDF·BPF·실시간 클래스 범위는 유지합니다. R2는 working set 식 바로 앞에 inactive_file이 커널의 회수용 inactive file 목록(LRU)에 속한 파일 기반 메모리 양이라는 최소 설명을 추가합니다. 항목 존재 조건·음수 방지식과 회수/재접근 비용·할당 성공 비보장 문장은 유지합니다
