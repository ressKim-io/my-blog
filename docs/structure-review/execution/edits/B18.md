# B18 수정 기록

담당: editor_b

## 편집 전 전문 독해와 연결 계획

- node-observability-sources: 전문·검토서 독해. 역할 그림 다음 usage/working set과 metrics-server 표본을 먼저 설명하고 endpoint/provider와 선언 지표를 뒤로 둡니다. eviction 보정은 표본 자체의 정의와 구분해 endpoint 뒤에 연결합니다
- container-log-files: 전문·검토서 독해. 도입 그림 뒤 현재 파일만 조회하는 범위와 API 중계를 먼저 둡니다. 기록 경로→형식→회전→follow/previous/GC를 연결하고 restart count 복구·symlink·종료 메시지는 보충합니다
- ephemeral-containers: 전문·검토서 독해. kubectl이 명세를 patch한다는 진입점을 앞으로 옮기고 서브리소스 기본 역할 다음에 kubelet의 시작/비재시작·PID 대상·별도 상태를 먼저 설명합니다. 필드 복원·허용 목록·다른 서브리소스 비교는 기본 실행 경로 뒤로 둡니다. 추가 전용 제한은 앞에 남깁니다

## 실제 변경


- 계획한 이동을 적용했습니다. 임시 컨테이너의 API→kubelet 흐름 그림도 기본 경로로 함께 이동했습니다
- logs의 현재 파일 조회와 중계를 앞당기고 기록·회전 이후 follow·previous를 읽도록 했습니다

## 미채택 제안과 이유

- 관측 소스 글의 로그 회전 설명은 삭제하거나 링크만으로 대체하지 않았습니다. 파일 수/크기와 API가 읽는 범위의 원문 사실·출처를 보존했고, 표본 보관과 다른 기록이라는 후반 단위에 유지했습니다
- 임시 컨테이너의 profile/권한은 상세를 모두 앞당기지 않았습니다. API 권한 분리와 추가 전용 제한만 먼저 알면 시작 경로를 이해할 수 있으며, 실제 설정을 만들고 PSA가 검사하는 상세는 후반에 남겼습니다

## 보존 대조와 기술 확인

- baseline 대비 front matter·fenced code·Markdown 링크/이미지·inline code 다중집합 보존 검사 실행 완료
- 지표 provider 조건·Window/Timestamp, 로그 형식·회전 복구·설계 이유 미확인, 임시 실행 실패·자원 영향·profile 버전 차이를 유지했습니다
- 기술 사실 신규 확인과 build·런타임 테스트는 실행 안 함. 자동 대조 외에 문맥의 지시어와 독자 질문을 재독했습니다
- 독자 질문: CPU 평균/메모리 표본, 과거 피크 기록 필요성, previous와 회전본 차이, 노드 파일과 API 조회 범위, 추가 저장/실행 차이, 상태 집계 제외/자원 영향 차이를 본문에서 확인했습니다
