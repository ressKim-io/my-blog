# B15 수정 기록

담당: editor_b

## 편집 전 전문 독해와 연결 계획

- kubelet-pod-lifecycle: 전문·검토서 독해. 도입의 Running/Ready 질문 뒤에 현재 상태 비교·probe·init/sidecar를 바로 연결합니다. kubelet 역할 두 문장은 앞에 남기고 syncLoop 입력표·PLEG 상세는 시작 순서를 읽은 뒤에 둡니다. readiness에서 Service와 EndpointSlice의 최소 역할을 설명하고 종료 경합은 원래 위치에서 완결합니다
- cri-oci-boundary: 전문·검토서 독해. 책임 그림 뒤 서비스 책임 두 가지는 유지하고 RPC 목록·endpoint·버전 상세를 OCI 기본 경로 뒤로 옮깁니다. sandbox의 namespace 옵션 분기를 create/start 뒤로 옮기며 rootfs 준비 책임은 bundle 앞에 배치합니다. 이미지 정책과 GC는 별도 후반 단위로 유지합니다
- runtime-isolation: 전문·검토서 독해. API/노드 경계 그림 뒤 capability/seccomp/AppArmor/SELinux의 역할을 먼저 읽고 필드 위치·우선순위를 읽도록 합니다. procMount의 경로 개수 상세는 생략 값과 capability 해석 뒤의 보충 단위로 옮깁니다. user namespace의 정책 버전 예외는 그대로 붙입니다

## 실제 변경


- 세 글 모두 위 계획대로 단락을 이동했습니다. lifecycle에는 readiness 상태가 EndpointSlice로 전달되는 연결 한 문장을 보완했습니다
- CRI 서비스의 책임 소개는 앞에 남겼고 상세 RPC·endpoint 설정은 실행 경로 이후로 옮겼습니다. containerd+runc 적용 범위, 두 create의 차이와 실행기/이미지 관리자의 책임은 유지했습니다
- runtime-isolation의 보안 기전 역할을 프로필 선택보다 앞에 배치하고 procMount 상세를 소제목으로 분리했습니다

## 미채택 제안과 이유

- runtime-isolation의 privileged 설명은 PSA 앞에 유지했습니다. PSA의 privileged 수준과 컨테이너 privileged 설정을 비교할 때 효과를 먼저 알아야 하며, user namespace 지원 예외를 합쳐 긴 단위로 만들 필요가 없습니다
- lifecycle의 sidecar 시작/종료 비교표는 나누지 않았습니다. 같은 선언의 수명을 비교하는 기존 설명이 유용하며 실제 종료 유예 상세는 뒤에서 이어집니다

## 보존 대조와 기술 확인

- baseline 대비 front matter 전체, fenced code, Markdown 링크·이미지 참조, 기존 inline code 다중집합 누락 없음 확인
- 상태·주기·gate·버전·소스·불확실성은 이동한 원문에 보존했습니다. 기술 주장을 새로 검증하지 않았습니다
- Python 3 대조 검사 실행 완료. build·런타임 테스트는 담당 제한으로 실행 안 함
- 독자 질문: Running/ContainersReady/Ready 차이, preStop의 전파 비보장, rootfs 준비와 실제 시작의 책임, CRI 시작 실패 시 단계 구분, baseline과 생략값의 차이, PSA와 이미지 사용자 검사의 차이를 본문에서 확인했습니다
