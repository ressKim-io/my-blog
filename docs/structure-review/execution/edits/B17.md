# B17 수정 기록

담당: editor_b

## 편집 전 전문 독해와 연결 계획

- eviction-oom: 전문·검토서 독해. 세 경로·OOM 증거 비교는 유지합니다. 자원 신호 소개 뒤 한 주기의 회수/축출/재평가를 먼저 두고 hard/soft와 순위로 세부를 풉니다. memory.available 정의는 working set 순위보다 먼저 두되 기본값 병합·notifier·PSI는 순위 후반으로 옮깁니다
- node-heartbeat-taint-eviction: 전문·검토서 독해. Lease/status 역할 다음에 controller 관찰과 유예 판정을 연결합니다. 직접 Lease 재확인 보호 뒤 Unknown 조건 변경으로 이어지도록 순서를 정리하고 taint→toleration→삭제/정리를 끊지 않습니다. report defaulting과 zone 속도는 기본 경로 뒤 보충합니다

## 실제 변경


- eviction-oom은 신호 소개 뒤 회수와 한 번 축출의 범위를 먼저 설명했습니다. 종료 유예의 지시어를 새 순서에 맞추고, 순위표는 회수 후에도 부족할 때 사용한다는 조건을 보완했습니다
- heartbeat는 실제 Lease 재확인 뒤 Unknown 판정 순서로 연결하고 Pod 삭제 경로를 zone 확장보다 먼저 마쳤습니다. 기본값과 조회 최적화는 별도 절로 이동했습니다

## 미채택 제안과 이유

- memory.available의 정의는 후반으로 모두 보내지 않았습니다. 순위에서 working set을 이해해야 하므로 기본 회수 주기 다음·순위 이전에 유지했습니다
- podGC와 out-of-service는 삭제 완료가 남는 이유와 연결해 유지했습니다. zone 정책은 이 단위를 마친 뒤 확장합니다

## 보존 대조와 기술 확인

- baseline 대비 front matter·fenced code·링크/그림·inline code 다중집합 보존 검사 실행 완료
- 1초/2초 종료 유예, 회수 조건, local storage 별도 범위, circuit breaker와 오류 전파, 각 타이머·가정·불확실성 보존
- 새 기술 검증은 실행하지 않았습니다. build·런타임 테스트는 담당 제한으로 실행 안 함
- 독자 질문: 종료와 후속 오브젝트 삭제, soft 발동/종료 유예, 50초+300초의 가정, Node Unknown과 Node 부재의 구분을 본문에서 확인했습니다

## 독립 검토 반영

R1: memory.available 계산 보충을 독립 H2로 승격했습니다. 한 주기 최대 한 Pod 설명의 하위 조건처럼 묶이지 않도록 범위를 분리했으며 앞뒤 신호·회복 문맥을 다시 읽었습니다
