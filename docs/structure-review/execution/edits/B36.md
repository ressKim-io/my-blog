## 편집 전 전문 독해와 연결 계획

### k8s-theory-mount-bind-mount

원문 전문과 검토서를 읽었습니다. mount가 경로를 가리는 설명 다음에 bind의 사용 결과·복제 아님·경로 문자열 링크 아님을 연결합니다. VFS 객체 표와 clone_mnt 구현은 그 결과를 해석하는 독립 절로 옮깁니다. 기존 재귀 bind 조건 뒤 CSI stage/publish 가정 예시와 정리를 설명하고, umount·열린 file 참조·lazy detach를 바로 붙입니다. umount 끝의 shared/slave 해제 전파 문단은 개념을 배우는 namespace/전파 절 뒤에 옮겨 선행 참조를 피합니다. readOnly·재귀·런타임 조건은 기존 위치와 범위를 유지합니다

## 실제 변경

- bind의 기존 트리 재사용 결과를 VFS 객체 설명보다 먼저 배치했습니다. VFS 표와 clone_mnt는 같은 파일 데이터와 별도 경로 연결의 구현 설명으로 모았습니다
- CSI 정리 바로 뒤에 umount·열린 파일·lazy detach를 연결하고 shared/slave 해제 전파 문단은 전파 정의 뒤로 옮겼습니다

## 미채택 제안과 이유

기존 재귀 bind 조건은 CSI 사례 앞에 유지했습니다. 사례에서 세는 mount 수의 전제와 이후 사건 전파의 차이를 이해하는 데 필요합니다. stage/publish 가정과 전체 mount 수의 비보편성, 읽기 전용 조건은 삭제하거나 줄이지 않았습니다

## 보존 대조와 기술 확인

baseline의 front matter·코드·링크·이미지·인라인 코드 보존 검사 통과. 재배치 전후를 재독해 데이터 복제와 경로 연결, 경로 제거와 마지막 참조, 사건 전파와 재귀 bind를 구분할 수 있는지 확인했습니다. 새 기술 사실 확인은 수행하지 않았고 별도로 발견한 미해결 기술 의문은 없습니다. 빌드·실행 테스트는 실행 안 함
