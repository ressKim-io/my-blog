# B22 수정 기록

담당: editor_b

## 편집 전 전문 독해와 연결 계획

- cni-contract: 전문·검토서 독해. 런타임 호출 뒤 버전표 대신 환경 변수/JSON 입력과 ADD 결과를 먼저 연결합니다. IPAM 위임을 단일 플러그인의 내부 책임으로 설명한 뒤 체인·실패 정리로 확장하고 버전/명령 표는 containerd 설정·STATUS 앞에 둡니다
- pod-sandbox-pause: 전문·검토서 독해. 생성·참조 유지·공유 범위 다음 앱 재시작/sandbox 재생성을 붙이고 IP·hostNetwork·준비 조건을 읽습니다. veth/bridge/eBPF 비교는 수명을 완결한 뒤 별도 전달 경로로 이동합니다
- overlay-native-routing: 전문·검토서 독해. 전달 방식 비교 뒤 MTU와 큰 패킷 실패를 붙입니다. IPAM 공급자 비교를 nodeipam 세부 앞에 두고 Node CIDR 기록/소비와 ENI 한도를 이어 읽습니다

## 실제 변경


- 계획대로 단락·그림을 이동했습니다. CNI에는 기존 명령표의 ADD 역할을 환경 변수/JSON 뒤에 짧게 풀었습니다
- sandbox의 빈 IP 조건 참조는 새 위치에서도 재생성 검사를 가리키도록 지시어를 조정했습니다
- overlay 글은 전달 방식/MTU를 완료한 뒤 공급자 표로 질문을 전환했습니다

## 미채택 제안과 이유

- CNI 실패 정리는 버전 표보다 먼저 유지했습니다. ADD 성공과 실패의 수명을 한 단위로 읽고 뒤에서 관리 명령 지원·자동 호출 여부를 대조하도록 했습니다
- veth 설명은 관련 글 링크로 대체하지 않았습니다. 기존 구현 예시와 모든 eBPF/Cilium 구성으로 일반화할 수 없다는 조건을 보존했습니다

## 보존 대조와 기술 확인

- baseline 대비 front matter·fenced code·링크/이미지·inline code 다중집합 보존 검사 실행 완료
- 구현별 버전·범위·호출 조건·실패 정리 비보장·MTU 가정·성능 미측정 유지
- 새 기술 검증과 build·런타임 테스트 실행 안 함
- 독자 질문: 호출자/결과 소비자·IPAM/체인·ADD 실패 정리, 앱 종료/namespace 수명·sandbox/app Ready, Node CIDR 부재와 IPAM·전달 방식의 성능 비단정을 본문에서 확인했습니다
