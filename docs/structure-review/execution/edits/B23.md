## 편집 전 전문 독해와 연결 계획

### k8s-theory-service-kube-proxy

원문 전문과 글별 검토서를 읽었습니다. 목록과 규칙의 구분은 명확하지만 EndpointSlice 크기와 네 가지 Service 타입을 지나야 첫 패킷의 DNAT와 응답 변환을 만납니다. 목록 분할 절을 conntrack 기본 설명 뒤로, 타입·headless 절을 UDP·용량 설명 뒤로 옮깁니다. ClusterIP 주소 할당 설명은 첫 패킷 앞에 남기되 IPVS 인터페이스 예외는 모드 비교에서 함께 읽게 합니다. iptables 체인 해시의 구현 문단도 첫 연결 뒤 모드 비교에 둡니다. 외부 접근 타입 뒤에 Local 정책과 NodePort 수신 주소를 연결하고, 모드 비교와 Cilium은 뒤에서 읽도록 합니다

### k8s-theory-service-cidr-ip-address

원문 전문과 글별 검토서를 읽었습니다. 주소 확보와 Service 저장이 별도 쓰기라는 질문에 대해 repair가 후반부에서야 응답합니다. 동적 후보 선택의 짧은 기본 절 뒤에 해제·repair 전체를 옮겨 성공·실패 경로를 닫고, 구간 offset은 그 뒤 독립 절로 둡니다. ServiceCIDR의 준비된 대역 역할은 후보 선택 첫 문장에 최소 설명으로 보완합니다. 주소군 변경·Ready의 버전 조건·삭제 보호·과거 bitmap 이행은 원문의 설명을 보존해 후반부에서 연결합니다

## 실제 변경

- Service: 목록과 패킷 역할 → ClusterIP 할당 → DNAT → conntrack 왕복을 먼저 연결했습니다. 목록 분할·UDP 상태와 용량 → 타입·headless → Local·NodePort → 모드 비교·Cilium 순으로 재배치했습니다. IPVS 인터페이스 조건과 체인 이름 구현도 모드 비교로 옮겼습니다
- ServiceCIDR: 동적 후보 선택 다음에 해제와 repair를 배치하고 offset 구간을 독립 절로 뒤에 두었습니다. 준비된 ServiceCIDR에서 후보를 찾는 역할만 첫 사용에서 보완했습니다

## 미채택 제안과 이유

ServiceCIDR의 IPAddress 필드와 parentRef 설명은 중복 판정 앞에 유지했습니다. 두 쓰기의 정합성과 repair가 어떤 기록을 대조하는지 이해하는 데 필요한 본문입니다. Service 글의 확률 예시와 ClientIP 조건도 첫 백엔드 선택의 의미를 바꾸므로 그 자리에 보존했습니다

## 보존 대조와 기술 확인

baseline과 front matter 전체·코드 블록·링크·이미지 경로·인라인 코드의 보존을 대조했습니다. 본문 이동 경계와 지시어를 다시 읽어 기본 연결 왕복, 목록과 기존 상태의 차이, Create 충돌과 repair 한계를 설명할 수 있는지 확인했습니다. 새 기술 사실 검증은 수행하지 않았습니다. 빌드·실행 테스트는 요청 범위에 따라 실행 안 함

## 독립 검토 반영

R1: UDP 정리의 첫 NodePort 참조에 노드의 포트로 Service에 접근하는 접점이라는 역할을 추가했습니다. serving endpoint 부재·다른 호스트의 같은 포트 흐름 삭제 위험은 그대로 유지했습니다
