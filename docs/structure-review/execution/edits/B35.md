## 편집 전 전문 독해와 연결 계획

### k8s-theory-netfilter-conntrack

원문 전문과 검토서를 읽었습니다. hook·table·chain의 최소 정의는 앞에 유지하고 nftables·전체 priority·ACCEPT 실행 상세를 첫 왕복 뒤로 옮깁니다. 수신 DNAT → KUBE-SEP 변환 → original/reply 예시 → 후속 NAT 재사용을 잇습니다. local OUTPUT 재라우팅·SNAT 등록 범위는 기본 왕복 뒤에 비교합니다. NEW 상태·namespace 공유 설명도 재사용 뒤로 옮기며 filter 점프의 NEW 조건은 그 상태를 배운 다음에 읽도록 합니다

### k8s-theory-namespace-lifetime

원문 전문과 검토서를 읽었습니다. task_struct/nsproxy 전체 설명은 runtime/CNI 정리 뒤로 옮겨 먼저 열린 FD·mount가 남는 이유와 network 비동기 정리를 완결합니다. 그림의 nsproxy는 프로세스 쪽 참조를 묶는 구조라는 역할만 인접 보완합니다. 다른 namespace·파일시스템의 참조 표는 커널 참조 상세와 묶고, setns 권한 절을 PID 비교 앞에 옮깁니다. 참여·실행 가능성과 /proc 관점은 network 정리 후의 비교로 남깁니다

## 실제 변경

- Netfilter는 기본 hook/규칙 단위 정의 뒤 DNAT·양방향 튜플·재사용을 연속 배치했습니다. local 재라우팅·전체 priority·NEW 상태·namespace 범위는 뒤로 옮겼고 SNAT 역할 정의는 첫 언급 곁에 남겼습니다
- Namespace는 참조 유지 → 커널 정리 → containerd/CNI 정리를 먼저 완결했습니다. task/nsproxy와 추가 참조, 참여 권한, PID 실행 가능성은 그 뒤에 비교합니다

## 미채택 제안과 이유

Netfilter의 두 진입점과 NAT 체인 기본 설명은 그림과 일치하도록 함께 유지했습니다. OUTPUT의 재라우팅 내부 함수만 뒤에서 상세 비교합니다. Namespace의 PID 구성 조건은 종류를 처음 구분할 때 이미 필요하므로 도입에 유지했습니다

## 보존 대조와 기술 확인

front matter·코드·링크·이미지·인라인 코드의 baseline 보존 검사 통과. 이동한 문단 전후를 재독해 SNAT 첫 정의, 상태 분류와 새 바인딩의 차이, 프로세스/객체/장치/IPAM 정리의 다른 범위를 확인했습니다. 새 기술 재검증은 하지 않았으며 별도로 발견한 미해결 기술 의문은 없습니다. 빌드·실행 테스트는 실행 안 함
