# B19 수정 기록

담당: editor_b

## 편집 전 전문 독해와 연결 계획

- workload-rollout-revisions: 전문·검토서 독해. 템플릿별 집합 그림에서 replicas 3 롤아웃으로 바로 연결하고 진행 판정·ReplicaSet 축소·undo를 Deployment 안에서 끝냅니다. 해시 충돌·selector 소유권은 집합 식별 심화로 묶습니다. DaemonSet은 대상 선정 뒤 교체, 이어 이력을 설명합니다
- job-cronjob-completion: 전문·검토서 독해. completions 6/parallelism 2 다음 중간/최종 조건을 설명합니다. Indexed와 successPolicy를 실패/성공 우선순위 앞에 묶고 podFailurePolicy 동작 이름도 평가 순서보다 먼저 풉니다. CronJob의 기존 회차 선택 사례는 유지합니다
- hpa-scale-subresource: 전문·검토서 독해. 첫 그림 다음 scale의 본체 표현·HPA Update·Deployment의 ReplicaSet 배분을 먼저 연결합니다. 이후 계산/보정/안정화를 상세하게 읽고 GitOps의 소유권 변화로 확장합니다. 결과를 바꾸는 readyPodCount·정수화·누락 조건은 식 옆에 유지합니다

## 실제 변경


- 계획한 단락 이동을 적용했습니다. Indexed 정의는 backoffLimitPerIndex의 첫 사용 전에 두고, successPolicy의 기존 중간/최종 조건도 유지했습니다
- Deployment의 기본 3 replica 사례 이후 진행 상태·축소 Pod 선정·undo가 이어집니다. DaemonSet의 교체와 이력 순서를 맞췄습니다
- HPA의 실제 Update와 워크로드 배분 관계를 계산 세부보다 앞에 두었습니다

## 미채택 제안과 이유

- HPA에 새 숫자 계산 예제를 만들지 않았습니다. 기존 단순식의 조건과 작은 편차/안정화/소유권 예시를 보존하고 쓰기 결과를 앞에서 연결했습니다
- ReplicaSet 삭제 순위의 세부는 삭제하지 않았습니다. Deployment가 줄인 목표를 Pod 삭제로 바꾸는 단위에 모았습니다

## 보존 대조와 기술 확인

- baseline 대비 front matter·fenced code·링크/이미지·inline code 다중집합 보존 검사 실행 완료
- 변경은 원문 단락 이동과 지시어 조정입니다. 기술 사실 신규 검증은 실행하지 않았습니다
- build·런타임 테스트는 담당 제한으로 실행 안 함
- 독자 질문: surge와 available·undo의 범위, Job parallelism과 실재 Pod 수·각 시간 기산점, HPA 추천/저장/실제 Pod 수·Deployment와 다른 쓰기 대상의 구분을 본문에서 확인했습니다

## 독립 검토 반영

HPA R1: scale 첫 문장은 목표 replica를 일반 갱신으로 기록한다는 역할 설명으로 바꾸고, 원문의 Scales Update와 SSA 대비 문장을 SSA의 필드 관리·충돌 정의 바로 뒤로 옮겼습니다. 연결 전후를 재독했습니다
