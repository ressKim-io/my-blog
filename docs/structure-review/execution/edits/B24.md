## 편집 전 전문 독해와 연결 계획

### k8s-theory-dns-ndots

원문 전문과 검토서를 읽었습니다. ClusterFirst의 search 표에서 ndots 사례로 바로 연결되도록 dnsPolicy·hostNetwork·설정 상한 두 소절을 NodeLocal 설명 뒤로 옮깁니다. CoreDNS 이름 종류 표와 Pod 이름 조건도 후반 보충으로 둡니다. 기본 예시 뒤에는 외부 이름 전달과 fallthrough 구분 → API 상태·응답 캐시 → resolver 재시도 → NodeLocal 순으로 연결합니다. API 관찰 절의 pods 모드 첫 참조는 역할을 함께 적어 뒤의 이름별 표 없이도 읽히게 합니다

### k8s-theory-traffic-locality-dual-stack

원문 전문과 검토서를 읽었습니다. 접점 표의 출발지 예외는 주장 범위에 필요하므로 유지합니다. 그 다음 SNAT 세부 소절을 뒤로 보내 Local 후보 제한 → 부재 판정 → Ready/종료 후보 → 선호 fallback을 먼저 읽게 합니다. SNAT와 no_local_endpoints 지표는 후보 선택 뒤의 효과·관측으로 연결합니다. dual-stack 시작에는 앞의 후보 판단을 주소군별로 반복한다는 연결만 보완하고 VIP·Slice·primary·headless의 기존 설명을 유지합니다

## 실제 변경

- DNS 정책 분기·상한과 이름별 레코드를 NodeLocal 뒤에 배치했습니다. 기본 search에서 ndots 질의 수 사례로 직접 이어지고, CoreDNS 전달·캐시와 resolver 재시도가 앞에서 닫힙니다
- 지역성의 SNAT와 지표를 후보 선택 뒤 독립 절로 옮기고 dual-stack의 주소군별 후보 연결을 보완했습니다

## 미채택 제안과 이유

DNS의 glibc·musl 차이는 ndots 규칙이 달라지는 핵심 조건이라 사례 앞에 유지했습니다. 지역성의 출발지 특수 처리 경고와 Ready·종료 조건도 앞의 정책 주장을 제한하므로 뒤로 미루지 않았습니다

## 보존 대조와 기술 확인

front matter·코드·링크·이미지·인라인 코드의 baseline 보존 검사를 통과했습니다. 이동 전후를 재독해 DNS 후보 증가와 응답 유실, 캐시 위치, Local의 원격 금지와 종료 후보 fallback·주소군별 목록을 구분할 수 있음을 확인했습니다. 새로운 기술 사실 확인은 수행하지 않았습니다. 빌드·실행 테스트는 실행 안 함
