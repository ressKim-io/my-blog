# 본문 구조 편집 실행 기록

2026-10-25 요청에 따라 71편의 본문 편집과 독립 검토를 마쳤습니다
기존 `posts/` 검토서와 manifest 해시는 편집 전 기준으로 유지합니다

- 본문 수정 71/71, 독립 검토 71/71, 미해결 편집 사항 0건
- [글별 상태](status.json)에서 수정 완료와 독립 검토 완료, 확인한 본문 SHA256을 따로 기록합니다
- [글 사이 연결 검토](integration-review.md), [실행 검증 결과](verification.md), [기술 재확인 범위](technical-followup.md)를 구분합니다

## 범위와 역할

- 대상과 묶음은 `../manifest.json`, `../batches.json`의 71편·36개 묶음입니다
- 수정자는 배정된 본문과 `edits/{batch}.md`·`edits/{batch}.json`만 수정합니다
- 독립 검토자는 해당 글을 수정한 사람과 분리하며 `reviews/{batch}.md`에 결과를 기록합니다
- 메인 에이전트가 상태 집계, 글 사이 연결·중복, 실행 검증을 담당합니다
- front matter 전체, 기존 자산, 사이트 코드, 기준 manifest는 보존합니다

## 절차

1. B02 PVC 글을 먼저 수정하고 독립 검토·반송·재확인을 거쳐 기준을 정합니다
2. 수정자는 원문 전문과 검토서를 읽고 실제 문단의 연결 계획을 기록한 뒤 편집합니다
3. 검토자는 글별 검토서·수정 기록을 보기 전에 수정 본문 전문을 먼저 읽고 독자로서 막히는 위치를 기록합니다
4. 그다음 편집 전 원문 전문과 검토서를 대조하여 사실·조건·코드·출처·그림의 보존을 확인합니다
5. 문제는 위치·독자가 막히는 이유·수정 방향을 적어 수정자에게 반송합니다
6. 수정된 부분과 앞뒤 흐름을 검토자가 다시 읽고, 확인한 본문의 SHA256과 함께 판정합니다

## 기록 규칙

수정 완료와 독립 검토 완료는 서로 다른 상태입니다
검토 완료는 지정된 버전의 본문을 읽은 결과이며, lint나 빌드 통과를 대신 적지 않습니다
기술적 재확인이 필요한 원문 주장은 별도 항목으로 남기고 이번 구조 편집에서 확인한 사실처럼 쓰지 않습니다
검토자가 직접 본문을 고치지 않습니다

- 이후 `verify.py`의 원문 해시·행·인용 위치 실패는 의도한 본문 편집과 구분해 해석합니다

## 실행 검증 계획

front matter, 코드 블록, 출처 URL, 이미지 참조를 원문과 비교하고 문서·본문 내부 링크와 MDX를 검사합니다
문체 lint와 ESLint를 실제 실행하고 최종 정적 빌드를 확인합니다
`prebuild`는 범위 밖 `CLAUDE.md`를 갱신하므로, 최종 빌드는 package.json의 실제 build 명령을 직접 실행하여 이 훅만 제외합니다
명령별 결과와 남은 범위는 실행 검증 기록에 따로 남깁니다
