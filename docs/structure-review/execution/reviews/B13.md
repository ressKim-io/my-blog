# B13 독립 검토 — review_a

## 첫 독해 기록

글별 검토서보다 먼저 수정본 두 편의 전문을 읽었습니다

- event-compression: Eventf에서 시작해 입구/소비자 큐를 나누고, 같은 Pod 실패의 설명 숫자만 달라지는 사례로 두 반복 키를 비교합니다. core의 집계→카운트→필터와 events의 첫째/둘째/셋째 관측을 각각 완결한 뒤 전송 제한/TTL/표시 숫자로 이어집니다. scheduler와 kubelet 선택은 동작 비교 뒤 실제 사용 사례로 붙습니다. 첫 독해에서 필수 수정 발견하지 않음
- distributed-tracing: 메트릭·조건부 로그·표본 span을 나눈 뒤 문맥 전파→추적기 설정→부모 신뢰→표본 선택→배치 내보내기를 읽습니다. 받은 부모와 link가 다른 이유를 알고 ParentBased의 0/생략을 만나므로 새 루트와 부모 선택을 섞지 않습니다. span 이름·kubelet 계측 다음에 filter 측정 종료와 utiltrace 로그의 상세를 비교합니다. 이동한 그림과 ‘앞에서 본’ 참조가 각 설명에 맞으며 필수 수정 발견하지 않음

## 원문 대조와 판정

두 baseline 전문과 글별 검토서를 대조했습니다. Event 글은 첫 파이프라인 소개 뒤 입구/소비자 큐를 설명해 어떤 관측이 집계에 도착하지 않는지 먼저 구분했습니다. 두 키의 차이는 원문에 이미 있던 설명 숫자 변경 조건을 가정 사례로 먼저 보여 줍니다. 긴 키 표 앞에서 비교 이유가 분명하며 본문 의미의 추가/삭제는 없습니다. core 집계키/반복키/spam키 차이, 서로 다른 메시지 10개·마지막 관측 뒤 600초, 카운트 우선/필터 후행, events 2회 전송 및 30분/6분/캐시 제거 조건, 1000/25 큐와 무기록 드롭, 50/100 전송 제한, 1시간 TTL/lease 재사용/no-op 조건을 모두 보존했습니다

추적 글은 부모 신뢰 판정을 ParentBased 앞에 두되 로컬 인증 span 예외는 표본기 설명 다음에 남겼습니다. 전파와 내보내기의 분리, 0/생략과 noop 차이, 신원별 부모/link, 계측 범위·HTTP 이름/속성 차이, SDK v1.44.0의 2048/512/5/30/10 조건·오류/드롭, TLS 환경 설정 우선순위와 실측 미확인 조건이 그대로입니다. filter 완료 지점과 defer 종료의 차이, 100ms/V3 및 utiltrace 500ms/5초/V2·64자 audit ID, head/tail sampling의 복구 불가 경계도 뒤의 측정 해석 단위에서 유지됐습니다

두 글 모두 원문 줄의 누락 없이 재배치와 필요한 연결만 추가했습니다. front matter·코드/에러·출처 및 내부 링크·그림을 대조했고 완료·미해결 0입니다. 외부 기술 재검증 및 빌드·테스트 실행 안 함(검토 범위). SHA는 동반 JSON에 기록합니다
