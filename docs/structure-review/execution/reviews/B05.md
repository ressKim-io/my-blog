# B05 독립 검토 — review_a

## 첫 독해 기록

글별 검토서·편집 기록 전에 수정 본문 세 편을 전문 독해했습니다

- admission-webhook-failure: AdmissionReview의 입력과 allowed/patch 출력을 연결한 다음 매칭→실패 정책→대기·재호출→외부 작업→CEL로 확장합니다. VAP 파라미터 설명 끝의 “VAP도 ... 이 문제를 해결하지는 않습니다”는 직전 문장과 중복이며 멀어진 총량 제한 설명을 지시합니다. 최소 한 문장 삭제를 권장합니다
- api-extension-points: 구현 책임→등록→discovery→클라이언트 선택→기능 활성→호환→장애 진단은 연결됩니다. MAP Policy·Binding·매칭을 설명했다는 Admission 순서 링크는 해당 글에서 내용을 찾기 어려워 대상 확인이 필요합니다
- api-priority-fairness: 첫 절이 분류·자리 배정·Limited 대기/거부·Exempt까지 완결합니다. WorkEstimate의 뜻이 계산보다 앞에 있고 NominalCL·handSize를 배운 뒤 LIST 상한으로 넘어갑니다. 세부 계산이 길지만 처음 경로를 대체하지 않습니다. 첫 독해에서 필수 수정은 발견하지 않았습니다

## 원문 대조와 판정

baseline 세 편 전문과 글별 검토서를 대조했습니다

- webhook: 원래 총량 제한 단락의 VAP 문장이 CEL 입력 단락으로 이동하면서 “이 문제”가 멀어진 것을 확인했습니다. 파라미터/Namespace와 대상 객체의 비원자성은 보존하되 바로 앞 중복 문장과 합치고 동시 총량·유일성 보장을 명시하도록 반송했습니다. Ignore 범위, VAP 설정 오류/표현식 오류, MAP 부분 변경, 버전별 면제 조건은 보존됐습니다
- API 확장: MAP Policy/Binding 설명에 연결된 링크의 대상 내용을 B04 전문과 비교해 불일치를 확인했습니다. webhook/CEL 글로 연결하도록 반송했습니다. 구현 책임·특수 core 경로·Available 검사 및 시간·discovery 협상·호환성/게이트 조건은 보존됐습니다
- APF: 첫 경로에서 Limited/Exempt 결과를 배운 뒤 분류·몫·차용·큐·비용 계산을 읽을 수 있습니다. 세부 LIST 계산은 NominalCL/handSize 정의 뒤로 옮겼고 1000 watcher 계산·상한·추정/실제 경로 차이·429 조건·메트릭/소스가 보존됐습니다. 미해결 0, 완료

형식 확인은 내용 독해의 보조로만 썼습니다. 외부 출처 재검증 및 빌드·테스트 실행 안 함(검토 담당 범위). 최종 SHA는 동반 JSON에 기록합니다

## 반송 수정 재독 — 완료

webhook의 CEL 입력→인가 질의→파라미터 조회→미발견 조건을 재독했습니다. Namespace 조건을 포함해 트랜잭션 비보장을 통합했고 “동시 요청의 총량·유일성”을 명시하여 이동 전 지시어 문제가 해결됐습니다. API 확장 글은 MAP 설정 설명 앞뒤를 재독했고 Policy/Binding 관계를 본문에서도 짧게 설명한 뒤 실제 해당 내용을 가진 webhook/CEL 글로 연결합니다. B05 3편 완료, 미해결 0
