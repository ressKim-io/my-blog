# B11 독립 검토 — review_a

## 첫 독해 기록

글별 검토서보다 먼저 수정본 두 편의 전문을 읽었습니다

- certificate-signing-delegation: 인증서 발급 결과와 요청별 사칭의 적용 범위를 먼저 나눴습니다. bootstrap token 역할을 짧게 설명한 뒤 CSR의 내용/서버가 기록한 신원→생성·승인·서명→합성 권한 이름으로 진행합니다. token 형식·폐기·legacy signer·갱신·서빙/Pod 인증서의 상세는 이후에 두어 새 노드의 기본 발급 흐름을 끊지 않습니다. 사칭도 원래 신원 검사→교체→후속 인가를 먼저 설명한 뒤 constrained 모드와 audit 경계를 비교합니다. 필수 수정 발견하지 않음
- kubelet-access: logs 한 요청에서 사용자 pods/log와 API 서버 클라이언트 nodes/proxy가 분리됨을 끝낸 뒤 주소/포트·TLS·인가 위임을 풉니다. 기본 경로 뒤 FineGrainedAuthz의 폴백과 metrics-server의 직접 접속을 비교해 주체를 혼동하지 않습니다. 캐시와 설정 기본값, 읽기 전용 포트, 터널과 별도 transport는 뒤의 확장으로 읽힙니다. 앞서/이 경로 등의 참조와 두 그림을 주변 문단에 맞춰 읽었으며 필수 수정 발견하지 않음

## 원문 대조와 판정

두 baseline 전문과 글별 검토서를 대조했습니다. 인증서 글의 bootstrap 최소 역할은 처음으로 이동하고 형식/만료 조건은 발급 경로 뒤에 남았습니다. legacy signer와 사용자 정의 signer 내용도 삭제 없이 후반으로 이동했습니다. CSR 생성/approve/sign·일반 갱신 권한의 구분, token 캐시와 만료의 차이, 70~90%와 365일의 다른 의미, CA 신뢰 및 요청자/DNS/IP 소유의 조건, gate 버전, 제한 사칭 폴백과 audit 한계를 보존했습니다

kubelet 글은 주소 소유 검사를 후반으로, 설정 기본값과 readOnlyPort를 한 단위로 옮겼습니다. 이때 “위 메트릭 핸들러”, “위 세 경로”를 명시한 세 경로와 “이 세 경로”로 바꿔 참조가 어긋나지 않습니다. HTTP 경로 권한 속성, FineGrainedAuthz의 Allow/Deny/NoOpinion/오류와 폴백 제외 경로, 2분/5분/30초 캐시, kubeadm Binding, 설정 우선순위 및 transport의 다른 검증·자격증명 조건을 보존했습니다. timeout 5초를 TCP 상한으로 단정하지 않는 불확실성도 유지합니다

front matter·코드/에러·출처 및 내부 링크·그림을 대조했고 두 글 모두 완료·미해결 0입니다. 외부 기술 재검증 및 빌드·테스트 실행 안 함(검토 범위). SHA는 동반 JSON에 기록합니다
