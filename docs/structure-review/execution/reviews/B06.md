# B06 독립 검토 — review_a

## 첫 독해 기록

글별 검토서·수정 기록에 앞서 수정 본문 두 편 전문을 읽었습니다

- resource-version: A/B 100→104 경쟁으로 클라이언트 재계산을 먼저 이해하고 생략/0 예외와 서버 CAS 재시도를 구분할 수 있습니다. etcd lease는 갱신 비교와 별도 수명 문제라는 문장으로 전환합니다. LIST 번호 예제가 앞의 표와 달라지지만 “별도의 예”임을 명시해 혼동을 막습니다. 필수 수정 발견하지 않음
- watch: LIST 100으로 초기 상태를 갖춘 뒤 watch를 연결하고, 105→140에서 삭제 누락 때문에 snapshot을 다시 받아야 하는 이유를 앞에서 해결합니다. Reflector·BOOKMARK·빈 번호/0·캐시 이력·LIST 의미론은 이 기본 경로 이후의 조건입니다. 일반 BOOKMARK와 초기화 완료 표식, etcd progress가 구분됩니다. 필수 수정 발견하지 않음

## 원문 대조와 판정

두 baseline 전문과 글별 검토서를 대조했습니다

- resource-version: Update 생략/0·Deployment/CR 차이·CAS·동일 바이트 쓰기 생략·v1.35 순서 비교 범위·compaction 비보장·lease TTL와 재사용 수치가 유지됐습니다. TTL 문단을 별도 글로 빼지 않은 것은 본문 보존 범위에 맞으며 기본 CAS 설명을 마친 뒤 읽기 커서로 전환하기 전 보충으로 읽힙니다. 미해결 0
- watch: Reflector의 일반/streaming 재시도 차이와 server/client gate, 빈 legacy watch의 문서/구현 차이, 두 이력과 410, GET/LIST 경로 차이가 그대로 남았습니다. “앞서 설명한 일관된 캐시 읽기”를 현 위치에서 이해 가능한 조건 설명으로 바꿨습니다. BOOKMARK를 캐시 시간표 앞에 두어 역할을 먼저 이해할 수 있습니다. 미해결 0

front matter·코드·전체 URL/도해 참조를 대조했습니다. 외부 기술 재검증 및 빌드·테스트 실행 안 함(검토 범위). 두 편 완료, SHA는 동반 JSON에 기록합니다
