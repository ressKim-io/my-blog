## k8s-theory-dns-ndots

- 시작·종료 SHA256: `a0f6bdde2dd5901366437cce163d1e215b770f47d18b502ac1b3996a9597bb82`

첫 독해에서 설정 주체와 resolver→search/ndots→조건을 고정한 외부 이름 조회→CoreDNS 전달·캐시→유실·재시도→NodeLocal로 이어집니다. dnsPolicy 예외와 모든 Pod 이름 형식이 기본 질의 예시를 가로막지 않습니다. 뒤로 옮긴 pods 모드는 앞 API 관찰 문맥에서도 이름 응답을 제어하는 설정이라는 역할을 설명합니다. 앞 절 ClusterFirst·앞의 세 접미사 지시도 실제 설명을 가리킵니다

원문 대조에서 cluster.local 가정·노드 search 병합, glibc ndots 1/ClusterFirst 5·musl search 제거 차이, 네 후보×두 유형=8의 전제·패킷 수 아님·NXDOMAIN/NODATA/SERVFAIL 차이·끝의 점 조건을 확인했습니다. 외부 forward와 fallthrough 구분, API watch와 부정 응답 캐시·기동 5초 비보장, resolver timeout 5/attempts 2·musl 2.5초 계산 조건, 같은 소켓 A/AAAA·single-request-reopen과 내부 복구 한계를 보존합니다. NodeLocal의 구간별 효과·TCP 종료 후 conntrack 즉시 소멸 아님, hostNetwork의 무경고 정책 fallback과 MissingClusterDNS 구분·Windows 제한, search 32/2048/255·nameserver 3과 API 거절 차이, Pod 이름의 pods 모드·headless/Ready 조건·실제 설치 버전 미확인도 남습니다

기술 확인 한계: 문서·KEP의 3 retries/30초와 glibc attempts 2가 달라진 이유는 원문처럼 미확인입니다. 이를 현재 기본값 또는 실측 지연으로 바꾸지 않았습니다
