# B04 독립 검토 — review_a

## 첫 독해 기록

글별 검토서와 수정 기록을 읽기 전에 수정 본문 세 편을 전문 독해했습니다

- authentication: 토큰 명세·발급·파일·요청·user.Info의 주체 구분은 첫 절에서 연결됩니다. 다만 구체적인 사용자 이름·그룹 결과가 Node gate·60초 예외 뒤에 있어 기본 요청의 산출물을 늦게 확인합니다. `만들어진 신원은 어떻게 인가에 전달되나`를 claim 상세 앞에 두면 더 자연스러운지 원문 대조에서 판단합니다
- authorization: prod/web의 list pods를 먼저 끝낸 뒤 규칙·체인·selector·권한 위임·진단으로 확장합니다. 필수 설명이 선행 링크에 의존하지 않으며 첫 독해에서 필수 수정은 발견하지 않았습니다
- admission-order: 일반 CREATE의 정상 저장 경로를 먼저 완결하고 ServiceAccount·LimitRanger 사례 다음 인터페이스 목록으로 넘어갑니다. 재호출·quota 별도 쓰기·PSA의 별도 Pod 요청도 앞의 모델로 설명됩니다. 첫 독해에서 필수 수정은 발견하지 않았습니다

## 원문 대조와 판정

세 편 모두 baseline 전문과 글별 구조 검토서를 대조했습니다. 원문 claim 예시·RBAC YAML, 모든 source URL·버전·수치·도해 참조·front matter가 보존됐습니다

- authentication: Node gate 표와 60초 상세를 기본 신원 결과보다 앞에 둔 문제를 필수 수정으로 반송했습니다. 일반 객체 상태 검증은 첫 인증 설명 곁에 남기고 삭제 허용 오차·Node 직접 binding 상세만 신원 전달 뒤로 옮기도록 요청했습니다
- authorization: Role/Binding의 선행 설명과 집계·위임 절 분리가 독자 질문에 대응합니다. NoOpinion·오류·403/500 조건, selector의 목록 필터 한계, masters 특권 범위가 유지됐습니다. 미해결 0, 완료
- admission-order: ServiceAccount/LimitRanger 사례가 인터페이스 표보다 앞에 왔고 PSA가 managedFields보다 앞에 왔습니다. GET/LIST/WATCH·PATCH 적용 차이, 재호출 비보장, quota 별도 쓰기, PSA 면제가 유지됐습니다. 미해결 0, 완료

구조·보존 검토이며 외부 기술 출처를 새로 검증한 결과는 아닙니다. 빌드·테스트 실행 안 함(검토 담당 범위). 최종 SHA는 동반 JSON에 기록합니다

## 반송 수정 재독 — 완료

일반 검증·audience 설명부터 user.Info 표, 삭제 중 객체/Node 상세와 갱신 절까지 앞뒤를 재독했습니다. 기본 신원 전달을 마친 뒤 60초·Node gate 예외를 읽는 순서로 고쳐졌고 일반 SA/Pod 존재·UID 조건과 전체 gate 정보는 유지됐습니다. B04 3편 완료, 미해결 0
