# B07 독립 검토 — review_a

## 첫 독해 기록

수정 본문 두 편을 글별 검토서보다 먼저 전문 독해했습니다

- object-identity-ownership: web의 aaa/bbb 재생성으로 질문을 푼 뒤 자식 ownerReferences, namespace와 다중 소유자 판정, 이를 유지하는 GC 그래프로 이어집니다. label/selector가 소유관계를 만들지 않는 설명은 GC 내부보다 앞에 있습니다. UID DELETE와 admission 권한은 별개 질문으로 구분되고 오류 표와 대응합니다. 필수 수정 발견하지 않음
- deletion-lifecycle: Service의 외부 정리와 Pod의 유예 종료를 먼저 구분합니다. 삭제 시작/최종 저장소 삭제, 목록 항목 제거/실제 정리, propagation과 GC 캐시 범위를 구분할 수 있습니다. generation·observedGeneration은 기본 삭제 경로 이후의 관찰 보충이며 Namespace 절이 실제 잔존 객체 확인으로 다시 연결합니다. 길이는 길지만 기초 삭제 절차를 중단하지 않습니다. 필수 수정 발견하지 않음

## 원문 대조와 판정

baseline 두 편 전문과 검토서를 대조했습니다. UID/GC 글은 DELETE precondition을 소유관계 뒤의 별도 활용으로 이동하고 label/annotation의 식별 한계를 앞에서 설명합니다. 다중 소유자·namespace·기본 비활성 admission·부모 finalizers update·가상 노드/부재 캐시·순환 비보장·discovery 부분 실패·annotation 한도가 모두 남았습니다

삭제 글은 finalizer와 Pod 경로를 전파 정책 전에 완결합니다. 200/202 구현 차이, 외부 정리 비보장, 마지막 DELETE와 UID, 유예 예외, Namespace 두 필드·discovery·조건 갱신 한계, generation 리소스별 차이와 관찰≠완료를 보존했습니다. generation을 삭제 본론 후 보충으로 둔 선택은 원문 내용 보존을 만족하며 마지막을 Namespace 잔존 조건으로 돌려 놓았습니다
