# B12 독립 검토 — review_a

## 첫 독해 기록

글별 검토서보다 먼저 수정본 두 편의 전문을 읽었습니다

- control-plane-high-availability: 같은 노드 장애에서 quorum·요청 분배·조정 리더를 따로 확인한다는 질문을 먼저 끝냅니다. 이후 캐시 최신성, APF 프로세스별 용량, learner와 세 종류의 Lease 차이가 추가 조건으로 읽힙니다. 리더 선출의 15/10/2초와 fencing 부재를 한 구간에 두어 정확한 전환 시간 보장으로 오해하지 않습니다. 첫 독해에서 필수 수정 발견하지 않음
- storage-transformations: codec과 transformer 경계 다음에 새 키 선택/기존 값 재기록의 차이를 먼저 설명하고, provider 접두사·읽기/쓰기 선택·stale 분기로 이유를 확인합니다. KMS의 KeyID와 키 자료 cache, 저장 위치 AAD, 손상 LIST는 기본 키 교체 뒤의 확장입니다. 같은 이름의 ‘키’가 etcd 경로인지 암호화 키인지 해당 절에서 구분하며 기본 예제의 이유 없는 교체 없음. 첫 독해에서 필수 수정 발견하지 않음

## 원문 대조와 판정

두 baseline 전문과 글별 검토서를 대조했습니다. HA는 API 서버 역할을 캐시/APF 세부에서 분리해 앞에 두고 controller 리더 선출을 이어 기본 호스트 장애의 세 역할을 완결했습니다. learner의 linearizable/serializable 구분은 이제 두 읽기 개념을 설명한 다음에 나오므로 전제도 충족합니다. quorum/분할 수치, watch의 RequireLeader/준비 상태별 위임·429 조건, APF 용량·버전차, etcd TTL과 identity Lease, fencing 한계 및 probe 시간 비보장을 모두 보존했습니다

저장 암호화는 API 읽기 권한과의 경계를 처음으로 옮겼고, 키 교체의 첫 사례에서는 아직 설명하지 않은 stale을 빼고 이후 stale/Update 절에서 의미를 다시 설명했습니다. 같은 내용의 Update 재기록이 사라진 것은 아닙니다. 읽기 후보/쓰기 첫 항목·오류 폴백, identity, 다중 서버 키 배포 순서와 백업 보존, revision 동시성 검사, KMS KeyID/키자료 유형·읽기 전용 캐시/24시간 조건, provider별 AAD, reload의 성공 조건·1분 비보장, 손상 LIST 최대 100 및 emulated gate 조건을 보존했습니다

front matter·코드/에러·출처 및 내부 링크·그림을 대조했고 두 글 모두 완료·미해결 0입니다. 외부 기술 재검증 및 빌드·테스트 실행 안 함(검토 범위). SHA는 동반 JSON에 기록합니다
