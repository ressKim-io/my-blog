외부 admission 판단이 실패하거나 정책에서 거부했을 때 원래 API 요청과 복구 작업이 어떻게 영향을 받는지 이해합니다

선행 개념: mutating·validating admission과 저장의 순서

## 원문 근거와 개선점

### L28 응답 구조를 알기 전에 실패 정책을 비교합니다

> ## Ignore는 정상적인 거부를 무시하지 않습니다

제목의 오해 교정은 유용하지만 처음 배우는 독자는 allowed:false와 통신 실패의 차이를 아직 보지 못했습니다. 다음 절에서 AdmissionReview를 읽고 앞의 표로 되돌아가야 합니다

수정 방향: 도입에 차이를 한 줄로 예고하고, 최소 AdmissionReview 요청·응답을 보여준 뒤 Fail·Ignore 표를 배치합니다

### L147 호출 대상 선택이 재호출 설명 뒤에 나옵니다

> ## 매칭 범위가 장애의 직접 영향 범위입니다

selector 때문에 첫 호출에서 제외된 webhook의 재호출 제한을 앞 절에서 설명하지만 selector가 무엇을 선택하는지는 뒤에서 나옵니다

수정 방향: 대상 선택 → 원격 호출 → 응답/실패 → 재호출의 순서로 기본 경로를 정리합니다

### L181 별도 정책 체계가 webhook 장애의 결론을 오래 미룹니다

> ## VAP는 규칙과 적용 방식을 나눕니다

VAP의 파라미터·입력·오류와 MAP까지 긴 설명을 통과해야 동시성·부작용·자기 복구 차단으로 돌아옵니다. 제목이 약속한 장애 범위를 한 번에 따라가기 어렵습니다

수정 방향: webhook의 지연·부작용·복구 순환까지 먼저 끝냅니다. VAP/MAP는 비교를 위한 두 번째 큰 단위로 구분하고 개별 오류 예외는 해당 기본 경로 직후에 붙입니다

## 권장 설명 순서

1. API 서버가 외부 HTTPS 판단을 기다린다는 관계와 최소 AdmissionReview 교환을 제시합니다
2. rules·selector로 어떤 요청이 호출 대상인지 먼저 정합니다
3. 정상 허용·정상 거부·판단 실패를 나누고 Fail·Ignore와 직렬/병렬 대기를 설명합니다
4. 변경과 재호출의 관계, Ignore가 처리하지 못하는 오류를 같은 호출 경로에 붙입니다
5. 동시 요청의 총량 검사, 외부 부작용, webhook 자기 복구 차단을 통해 운영 영향 범위를 완성합니다
6. VAP의 Policy/Binding 기본 평가를 하나의 replicas 예제로 설명한 뒤 파라미터·오류 처리를 확장합니다
7. MAP의 변경 방식·소유권·부분 변경·버전 조건을 별도 단위로 설명하고 통합 진단표로 마칩니다

## 유지할 내용과 조건

- Ignore는 정상 거부를 무시하지 않으며 일부 내부 오류도 처리하지 않음
- VAP 설정 오류와 표현식 오류의 다른 경로, MAP 부분 변경, 문서와 확인 소스의 차이
- API 기반/정적 설정 면제 및 버전·gate 조건, 모든 GET·LIST·WATCH를 막는다는 일반화 금지
